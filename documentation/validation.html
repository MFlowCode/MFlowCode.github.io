Validation

This page records what MFC has been checked against: exact solutions, reference data and conservation laws. Each section is one family of checks. It gives the status, the code version, the setup, the reference, the measured values with signed errors, and the limits. Every check has an example in examples/ with a checker script and a README, and a small version of it runs in the test suite (./mfc.sh test).

Status words: validated (agrees with the reference within the stated error), partially validated (agrees where measured; a regime or quantity is open), open discrepancy (disagrees, cause known or not), comparison only (reference data are qualitative). Errors are (MFC − reference)/reference.

Separate pages: Wall-normal ghost velocity at viscous walls (ib_wall_order against plane Poiseuille and Taylor-Couette flow). Other pages: Gas-phase chemistry (ignition, flame speed, reactive shock tube). Gas-dynamics pages: Shock tubes (Sod, Lax, 123 and Shu-Osher), Vortex order of accuracy (isentropic vortex, Taylor-Green decay), Circular blast wave, Positivity at a near-vacuum collapse. Reacting-flow pages: Detonation (1D CJ front speed and state, 2D cell width), Flame-vortex interaction (2D pair, 3D ring), Burning carbon body (cylinder and sphere burn rate). Multiphase pages: Two-fluid flows (water-air shock tube, interface advection, phase-change equilibrium), Bubble dynamics (Keller-Miksis collapse), Surface tension (Laplace pressure jump), Interface instabilities (viscous Rayleigh-Taylor growth rate).

Moving-body kinematics

Status: validated. Code: master at 067f23074, with the stage-consistent position update of #2040. Examples: examples/2D_mibm_constant_acceleration, examples/3D_mibm_wall_collision.

Two-way coupled bodies (moving_ibm = 2) are advanced from the force on them. Particle-resolved runs depend on the integration being exact where an exact answer exists, and on collisions returning the prescribed restitution.

The restitution error is first order in the steps per collision. At the default of 20 steps, expect a few percent in e at low e. The small cases run in the test suite as 2D -> IBM -> Moving Circle -> Constant Acceleration and 3D -> IBM -> Wall Collision -> Normal and -> Sliding Friction. The tables above were measured with GNU 13.3 (CPU, one rank). The golden tolerance is 1e-6 for both. Against goldens generated on the current master, the GNU, Intel, NVHPC and macOS CI lanes agreed to 1e-13 absolute on the fields and 5e-9 relative on the contact force; the checker scripts validate the physics, and the golden is a regression guard. Both tests are skipped in the single-precision lane. The sticking case is checked by check_collision.py and is not a golden, because the friction direction there depends on round-off.

Thermally developed channel

Status: validated (plane channel; the same source in particle arrays is not). Code: master at 1e3f1be0b, with the thermally developed source mean_temp_wall of #2200. Example: examples/2D_thermal_channel.

Periodic flow with a heated or cooled wall never reaches a uniform temperature, so the mean-temperature source (mean_temp, mean_temp_wall) removes the streamwise decay: it solves for the periodic part \(\psi\) of the thermally developed state \(T = T_s + \psi\,e^{-\beta x}\) Sun et al. [88] and holds the mixing-cup temperature at its target. A plane channel with isothermal walls has an exact developed Nusselt number, so it tests the source, its decay rate \(\beta\) and the wall heat transfer together.

Item Value
Geometry 2D plane channel, gap \(H\) = 34.28 µm ( \(D_h = 2H\)), periodic length 25 cells
Gas air (O2 0.233, N2 0.767 by mass, h2o2.yaml, reactions off), 1 atm, mixing-cup \(T_m\) held at 300 K, bulk Mach 0.1 ( \(U_b\) = 34.8 m/s), \(\mathrm{Re}_{D_h}\) = 150, \(\mathrm{Pe}_H\) = 53.3
Boundaries x periodic; y no-slip isothermal walls (bc_y%beg = bc_y%end = -16) at \(T_s\) = 330 K (hot) or 270 K (cold)
Numerics WENO5 (mapped), HLLC, SSP-RK3, fd_order = 4, mixture-averaged transport, fixed \(\Delta t\) = 0.4 \(\Delta y/(U_b + a)\)
Drive and source mean_mflux and mean_dpdx (gain 0.05); mean_temp = 300 K (gain 0.05) with mean_temp_wall = \(T_s\)
Reference constant-property laminar flow between parallel plates, constant wall temperature, fully developed: Nu = 7.5407 Shah and London [82]. With axial conduction at the run's \(\mathrm{Pe}_H\), the eigenproblem \(\psi'' + (6\,\mathrm{Pe}_H\,\eta(1-\eta)\,b + b^2)\psi = 0\), \(\psi(0) = \psi(1) = 0\), \(b = \beta H\), gives Nu = 7.5417 and \(\beta H\) = 0.14122; check_nu.py solves it
Measured mean_temp.dat ( \(T_m\), \(\dot q\), \(V_f\), \(\beta\)) and the last save, by check_nu.py

\(\mathrm{Nu}_\mathrm{src} = q_w D_h/(k(T_s - T_m))\) takes the wall heat from the source total, \(q_w = -\dot q V_f/(2L_x)\), which equals it at steady state. \(\mathrm{Nu}_\mathrm{grad}\) takes it from the temperature gradient at the walls (second-order one-sided) and does not use the source. The pair value uses half-differences between the hot and the cold run, which cancels viscous heating and the first-order property asymmetry. Averages are over the last 10 % of the steps; the state is developed by about 0.1 \(H^2/\alpha\).

  • Before the removal a single run was biased by viscous heating and by the property change across the gap, with opposite sign for the hot and the cold wall (32 cells: \(\mathrm{Nu}_\mathrm{src}\) 7.507 (−0.46 %) hot, 7.600 (+0.77 %) cold; \(\mathrm{Nu}_\mathrm{grad}\) 7.141 (−5.3 %) and 7.998 (+6.1 %)). With the dissipation removed the two estimates of a single run agree within 0.4 % at Mach 0.1, and what is left (hot −2.2 %, cold +2.7 %) is the property asymmetry, which the pair cancels. At Mach 0.3 the hot run's estimates differ by 1.1 %: the near-wall part of the dissipation that the cell-centre \(\tau : \nabla u\) misses.
  • \(\beta H\) of the pair mean is 0.1414 at 32 cells (+0.15 % against 0.1412) and 0.1413 at 64 (+0.06 %); the hot and the cold value differ from it by the property effect on the Peclet number.
  • The source total and the wall gradient agree within 0.1 % after pairing: the source removes the heat that crosses the walls, which closes the fluid energy budget.
  • The mixing-cup temperature is held to 2e-8 (32 cells) and 7e-9 (64 cells) of its target.

Limits:

  • Plane channel only. In periodic arrays of spheres \(\beta\) drifted by more than 1 % and the hot-wall and cold-wall runs disagreed (12 cells per diameter, cause not understood); do not take an array Nusselt number from this source (note under mean_temp_wall in the case-file documentation). The viscous dissipation is removed with the cell-centre velocity gradients, which miss about 1 % of the wall heat next to the walls at Mach 0.3.
  • Near-wall velocity sawtooth (open). With the no-slip isothermal wall (bc_y%beg = -16) the streamwise velocity in the first four cells next to each wall alternates about the Poiseuille profile by up to 12 % of \(U_b\) (32 cells, hot wall: \(u/U_b\) = 0.195, 0.147, 0.459, 0.543 against 0.092, 0.268, 0.432, 0.584). It is steady, uniform in \(x\) and symmetric, and the temperature is smooth; the Nusselt numbers above are not affected at the 0.2 % level. The cause is not verified.
  • Round-off sensitivity. With the default mapped WENO5 and weno_eps = 1e-16, the transverse momentum in the wall rows differs by 2 to 3 % between a GNU 13 -O3 build and a debug build after 20 to 200 steps. The registered test therefore uses non-mapped WENO3 with weno_eps = 1e-6, where the builds agree to 5e-8 (relative), and an AMD MI250X (Cray Fortran, OpenMP offload, one GCD) run agrees with the GNU CPU golden to 8e-8.

Reproduce

./mfc.sh run examples/2D_thermal_channel/case.py -t pre_process simulation -n 1 -- --ny 32 --nx 25 --tw 330 --tend 0.3
python3 examples/2D_thermal_channel/check_nu.py <hot run directory> <cold run directory>

The cold run uses --tw 270 in a copy of the directory (the output is written next to case.py). The tables were measured with GNU 13.3 (CPU, one rank, -O3). The suite runs the first 100 steps of the hot case as 2D -> Chemistry -> Thermal Channel -> Wall Temperature; its golden holds the conservative fields, and the tolerance is 1e-6 (GNU 13 double -O3, reldebug and debug agree to 5e-8, AMD MI250X and an AMD CPU build to 8e-8 and 6e-8; single precision differs from double by 4e-4, so the test is skipped in that lane).

Adding a section

One ## section per family, with an anchor {#sec-validation-<family>}: status and code version, one setup table per check, the reference and how it was obtained, a results table with signed errors, and the limits. Put each check's example, checker script and README under examples/, and register a small version in toolchain/mfc/test/cases.py. Cite references with \cite keys from docs/references.bib.

Keeping the goldens current

The registered tests are regression guards: their goldens hold the output of the code at the time they were generated. When a default or an algorithm in the numerics a test exercises changes (for moving bodies, for example the ib_mass_relax default), regenerate the goldens with ./mfc.sh test --generate --only <UUID> in the same change, and re-run the checker scripts to confirm the physics results above. A case whose tolerance must be looser than the default takes override_tol chosen from the spread between compiler and device lanes (Testing).
